# sdlc-tools

개발 생명주기를 위한 커맨드라인 도구 모음으로, 사람과 AI 에이전트가 함께 쓰도록 설계되었습니다. 모든 도구는 기본적으로 짧게 답하고, `--json` 을 주면 전체 결과를 JSON 문서 하나로 출력합니다. 인자나 자격 증명이 빠져 있으면 네트워크를 건드리기 전에 실패하고, 서버가 401, 403, 404 를 돌려주면 다음에 무엇을 해야 하는지 알려 줍니다.

## 하나의 규약

터미널 앞의 사람과 셸을 다루는 에이전트는 CLI 에 같은 것을 바라고, 같은 습관에 실망합니다. 읽기엔 너무 길거나 행동하기엔 너무 짧은 출력, `Error: Request failed` 같은 오류, 아무것도 알려 주지 않는 잘못된 플래그, 모든 실패에 `1` 을 쓰는 종료 코드가 그렇습니다. 이 저장소의 도구는 하나의 규약을 공유하므로, 한 도구에서 익힌 것이 다음 도구에도 그대로 이어집니다.

| 동작                | 얻는 것                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| 기본은 짧게         | 읽기 위한 몇 줄. `--json` 은 전체 결과를 stdout 에 JSON 문서 하나로 출력합니다.                            |
| 로컬에서 먼저 실패  | 빠진 인자, 옵션, 자격 증명은 요청을 보내기 전에 알려 줍니다.                                               |
| 틀리면 도움말       | 알 수 없는 커맨드나 플래그에는 해당 커맨드의 사용법과 오타 제안을 함께 출력합니다.                         |
| 의미 있는 종료 코드 | `0` 성공, `2` 사용법, `3` 인증, `4` 권한, `5` 없음, `6` 서버, `7` 네트워크.                                |
| 도움이 되는 오류    | 401, 403, 404 는 원인 후보와 다음 행동이 담긴 문장이 됩니다. `--json` 에서는 stderr 의 오류도 JSON 입니다. |
| 키체인에 자격 증명  | 토큰은 운영체제 자격 증명 저장소에 두고, 설정 파일에는 두지 않습니다.                                      |
| 내장 주소 없음      | 호스트, 프로젝트 키, 필드 id 는 플래그, 환경 변수, 설정에서 받으며 코드에 박지 않습니다.                   |

전체 명세는 [`packages/core`](./packages/core/README.ko.md) 에 있습니다.

## 패키지

| 패키지                                                   | 용도                                                                                                                                                                                            |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`@sdlc-tools/core`](./packages/core/README.ko.md)       | 도구들의 기반: 키체인 자격 증명, OAuth 2.0 PKCE 로그인, 오류·종료 코드 모델, HTTP 클라이언트, 인자 파싱, 출력 규약.                                                                             |
| [`@sdlc-tools/forgejo`](./packages/forgejo/README.ko.md) | Forgejo·Gitea 풀 리퀘스트 클라이언트(`sdlc-forgejo`): OAuth 또는 토큰으로 로그인하고, 풀 리퀘스트를 열고 리뷰하며, 상태·승인·머지 방식의 정책을 설정해 그에 따라 머지하고, 브랜치를 정리합니다. |
| [`@sdlc-tools/jira`](./packages/jira/README.ko.md)       | Jira Cloud 클라이언트(`sdlc-jira`): 이슈 검색·조회·생성·수정·전환·담당자 지정·코멘트와 작업 시간 기록. OAuth 또는 API 토큰으로 로그인하고 자격 증명은 키체인에 저장합니다.                      |

각 도구는 `packages/` 아래의 독립 패키지로, 버전을 따로 관리하며 `@sdlc-tools/core` 에만 의존합니다.

## 커맨드 이름

도구 패키지는 `sdlc-<tool>` 이라는 실행 파일 하나를 설치합니다.

제품 이름만 쓰면 이미 그 이름을 쓰는 프로그램과 충돌합니다. Forgejo 서버 바이너리는 `forgejo` 이고, 여러 Jira 커맨드라인 클라이언트가 `jira` 를 설치합니다. 둘을 한 `PATH` 에 두면 하나가 조용히 다른 하나를 가립니다. `sdlc-` 접두사를 붙이면 기존 도구 옆에 모든 도구를 설치할 수 있고, 셸 자동 완성에서도 한 계열로 알아볼 수 있습니다.

이 형식은 `git` 이 외부 서브커맨드를 찾는 방식(`git foo` 는 `git-foo` 를 실행)과도 같으므로, 이름을 바꾸지 않고도 나중에 `sdlc <tool>` 디스패처를 추가할 수 있습니다.

## 이 저장소에서 작업하기

Node.js 22.13 이상과 [pnpm](https://pnpm.io) 이 필요합니다. 저장소는 `package.json` 에 pnpm 버전을 고정합니다.

```sh
pnpm install
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

다섯 명령은 깨끗한 클론에서 이 순서대로, 사전 빌드 없이 동작합니다. 패키지끼리 `@sdlc-tools/source` export 조건으로 TypeScript 소스를 서로 노출하므로 린트, 타입 검사, 테스트는 항상 최신 소스를 봅니다. 규칙, 릴리스, 새 도구 패키지를 추가하는 방법은 [CONTRIBUTING.md](./CONTRIBUTING.md) 를 보세요.

## 보안

자격 증명은 macOS 키체인, Windows 자격 증명 관리자, Linux Secret Service(대체 수단은 커널 키링)에 저장하며, 도구와 서버를 키로 묶어 토큰이 발급한 서버에만 전달되게 합니다. 자격 증명처럼 보이는 키가 들어 있는 설정 파일은 거부합니다. 자세한 내용과 프로젝트 수준 설정의 위협 메모는 [`@sdlc-tools/core` README](./packages/core/README.ko.md#보안-참고) 에 있습니다.
