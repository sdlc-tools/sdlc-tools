`auth login --oauth` signs in to Jira Cloud with OAuth 2.0 (3LO) in the browser, as a confidential client of an OAuth app you create. The client id and the fixed callback port come from the `clientId` and `callbackPort` settings (user file, `SDLC_JIRA_CLIENT_ID`, `SDLC_JIRA_CALLBACK_PORT`, `--client-id`, `--callback-port`); the client secret is typed at a prompt that does not show it or piped in with `--client-secret-stdin`, and is kept in the keychain only. Later sign-ins for the same client id reuse the stored secret without asking; `--client-secret-stdin` replaces it, and a stored secret the server refuses says so. After sign-in the cloud id of the configured site is resolved (a site that was not allowed fails and names the allowed ones), and every command then calls the Jira API through `api.atlassian.com`. Access tokens are renewed before they expire and once after a 401, and the rotated refresh token is written back to the keychain. `auth status` shows the kind of credential (`oauth` or `token`) and the expiry of an OAuth access token, and `auth logout` removes the client secret too. API token sign-in is unchanged.
